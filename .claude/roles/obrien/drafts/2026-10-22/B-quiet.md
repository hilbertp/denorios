# Nothing runs between landings: the per-push suite, its fix requests and its pill go

<!-- Lane: core (docs/adr/ADR-PROOF-LANES.md). Removes a behaviour (automatic fix requests). ADR-JULIAN-ALONGSIDE §9 item B, Rule 5. Lands after A. -->

## What is broken / Goal

GitHub runs the safety-net suite on every push to dev, and the dashboard turns a red run into a fix request in Alex's inbox by itself. Six were ever filed. None was a slice bug caught early: five were one pre-existing failure on chore and handoff commits, the sixth was the pipeline's own bookkeeping (a lock regenerated by the next landing). Philipp did not know the run existed. ADR-JULIAN-ALONGSIDE Rule 5 decides that the only suite runs in the pipeline are Philipp's merge presses.

After this lands: `ci.yml` does not run on a push to dev (a person can still start it by hand or through a pull request to main); the dashboard files no fix request, keeps no per-push state, shows no per-push pill and no "Per-push checks (ci.yml)" line; the Regression panel reports the latest promote run only; and the prompts and role files stop telling Sam and Jordan that GitHub runs a suite when the slice lands.
