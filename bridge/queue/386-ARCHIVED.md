## Summary

The orchestrator now reads the session's own numbers once and writes them into the
report; Rom leaves the three machine metrics at 0 and is never failed for them.

`sessionTelemetry(stdout, durationMs)` reads the CLI's final `result` event and
returns `{ tokensIn, tokensOut, tokensCacheRead, elapsedMs, costUsd }`.
`total_cost_usd` wins whenever the output carries it — it is the only figure that
prices cache reads — and `computeCost` survives as the fallback only. A number the
output does not carry is `null`, never a zero that would read as a measurement.
`fillDoneMetrics(doneContent, telemetry)` rewrites the frontmatter of the queue
copy with those numbers plus two new keys, `tokens_cache_read` and `cost_usd`. The
`incomplete_metrics` ERROR path is gone; `validateDoneMetrics` keeps its name and
its `{ ok, invalid }` shape but only warns, and only when a machine metric is
still null after filling. The timesheet row, the DONE register event,
`closeSliceBlock`, `recordSessionResult` and `extractRomTelemetry` all now read
the one telemetry object, so one run can no longer carry three cost figures.
`buildDoneTemplate` is factored out of `invokeRom` and exported, and its words no
longer ask for numbers Rom cannot see.

Note on this report's own metrics: `tokens_in`, `tokens_out` and `elapsed_ms`
above are a best guess, as the brief's "How to finish" instructs, because the
running daemon still carries the pre-386 code and still files a zero as ERROR.
`elapsed_ms` is real (measured from the pickup timestamp in the template).
`tokens_in`/`tokens_out` are estimates and should not be read as measurements —
the real figures are in the `result` event at the end of `bridge/logs/rom-386.log`,
and once this slice is live the orchestrator overwrites these fields from it.
