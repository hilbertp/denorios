## Summary

`createWorktree` now gives every workspace its dependencies before it hands the path back. It
symlinks the main checkout's `node_modules` into the new worktree — on both of its exits, the
fresh-create path and the requeue-reuse path — so Rom, Nog, Bashir and the merge path are all
covered from one place. Nog's path calls the same function on the workspace it settled on, because
the common case reuses Rom's existing worktree and never reaches `createWorktree` at all.

A symlink was chosen over `npm ci` deliberately. Every workspace is a worktree of this repo at the
same lockfile, so the dependency tree is identical to the main checkout's by construction; the link
costs one syscall where an install would cost tens of seconds *per slice* — the third trap. Nothing
runs `playwright install` and nothing sets `PLAYWRIGHT_BROWSERS_PATH`, so Playwright keeps using the
browsers already cached machine-wide in `~/Library/Caches/ms-playwright`.

The trailing-slash hazard is fixed in the same slice, as the brief required. `node_modules/` means
"directory only" and git sees a symlink as a file, so with the slash the link is untracked-and-visible
and the first `git add -A` commits it. `.gitignore` now carries the slashless `node_modules`, with a
comment saying why so nobody puts the slash back. I reproduced the hazard rather than assuming it: with
the slash restored, `git status --porcelain` in a provisioned workspace reports `?? node_modules`; that
reproduction is kept as a control assertion inside the trap test.

The function is idempotent and never fatal. A dangling link is replaced rather than skipped
(`existsSync` follows a link and answers false for a broken one, so the check is `lstat` first). A
main checkout with no `node_modules` — which is exactly CI's `test` job, "pure Node, no install step" —
logs a warning and lets the slice continue.
